# ミューテーション検証を作業ツリー無改変で行う（go test -overlay）

**いつ使うか**: レビュー対象をWIPコミット等で固定している最中に、回帰テストの検知力（ガードを外したら本当に赤くなるか）を実測したいとき。「レビュー中は緑を壊す作業を止める」という運用ルールと、「テストの検知力を実測する」という品質要件を両立させたい場合に使う。

## 背景

回帰テストを追加しただけでは「守っている証明」にならない（`tasks/lessons.md` 2026-07-29参照）。ガードを実際に外して赤くなることを実測する必要があるが、レビュー対象を固定している最中に作業ツリーを直接改変すると、レビュアーが見ている内容と実際のコードがずれてしまう。

Goの`go test -overlay`は、指定したファイルパスを別ファイルの内容に差し替えてビルド・テストできる機能。**作業ツリーのファイルは1バイトも変更せずに**、改変後のコードでテストを実行できる。

## 手順

1. 改変したい元ファイルの絶対パスを確認する
   ```bash
   realpath internal/sse/conn.go
   ```

2. 元ファイルをスクラッチ領域にコピーし、そこに検証したい改変（ガードの削除など）を加える
   ```bash
   cp internal/sse/conn.go /tmp/claude-*/scratchpad/mutated_conn.go
   # Edit ツールで /tmp/.../mutated_conn.go を改変（例: closeOnce.Do(...) を素の close(c.done) に）
   ```

3. overlay用のJSONファイルを作る。`Replace`に「元の絶対パス→差し替え先の絶対パス」を書く
   ```json
   {
     "Replace": {
       "/home/user/repo/internal/sse/conn.go": "/tmp/claude-.../scratchpad/mutated_conn.go"
     }
   }
   ```
   複数ファイルを同時に改変する場合は`Replace`に複数エントリを追加する。

4. overlayを指定してテストを実行する
   ```bash
   go test -overlay=/tmp/.../overlay.json -run TestHTTPConn -v ./tests/unit/...
   ```
   ガードが機能していれば、狙ったテストが赤くなることを確認する。

5. 検証後、一時ファイル（コピー・overlay.json）を削除し、作業ツリーが無改変であることを確認する
   ```bash
   git status --porcelain   # 出力なしであること
   git diff                 # 出力なしであること
   ```

## 注意点

- `-overlay`は同一パッケージ内の他ファイルからの参照や、importパスの解決には影響しない。パッケージ構成を変えない範囲のミューテーションに向く。
- 検証後は必ず一時ファイルの削除と`git status`の確認をセットで行う。報告には「復元済み・`git status`空を確認」まで明記する（`tasks/lessons.md`のミューテーションテストの教訓参照）。
- レビュー依頼中に使う場合は、対象コミットハッシュは触らずに検証だけが完結する点をレビュアーに伝えると、レビュー対象固定の意図が正しく伝わる。

## 実績

Wave B-2レビュー（そら・ずんだもん）で、`internal/sse/conn.go`の防壁2（20回ループ要件）や`httpserver.go`の`BaseContext`能動キャンセルの検知力実測に使用。作業ツリーを変更せずに複数のミューテーションパターンを検証できた。
